# MDR-0011 问题 4 的资源守恒：不得延长时间范围

日期：2026-09-12 · 状态：已采纳 · 关联问题：问题 4（并统一问题 3 的资源区域口径）

## 问题

题目问题 4 允许对 C 类计划"改间隔"。间隔 g 出现在结束时刻里：

  e_i = s_i + d_i + (n_i − 1)(d_i + g_i)，

因此把 g 调大会把该计划的最后一次使用推到更晚，从而把整个方案的最晚结束时刻 T_end 推后。题目在问题 3 中明确写了"在不增加时频资源的前提下"，在问题 4 中没有重复这句话。于是产生歧义：**问题 4 的"改间隔"是否允许占用原本没有被使用的时间？**

v0.9.0 采用"不设限"读法，得到撤销向量 (0,0,9)，但把最晚结束时刻由 643Δt 延长到 718Δt（+11.7%），并在局限中承认"加入硬约束 e_i ≤ 643 重解的变体本轮未做"。评审复算指出：加上该约束后撤销向量反而是 (0,0,8)，**严格优于**不设限时找到的 9。也就是说 v0.9.0 既没有守住资源，也没有换来更好的解。

## 备选方案

1. **不设限（v0.9.0 的做法）**：动作集合只受 |Δg| ≤ 10、g′ ≥ 1 约束。方案可以任意延长时间范围；"不增加时频资源"只对问题 3 生效。
2. **以 e_i ≤ T_end 为硬约束**（T_end 取原始 150 个计划的最晚结束时刻 643Δt）：把"不增加时频资源"理解为对整个消解问题一致成立的守恒条件——可用的时频资源就是原始计划已经张成的区域 [0,100) × [0, T_end)。
3. 以 e_i ≤ T_end 为软目标（加入词典序的某一级）。

## 决策与理由

**采纳方案 2，并同时给出方案 1 的结果作为对照。**

- **口径一致**：问题 3 的资源区域本来就取 100 × T_end；若问题 4 可以自由延长 T_end，则同一篇论文对"时频资源"用了两把尺子。方案 2 使两问共用同一个区域定义，而且这个区域只由**原始数据**（问题 1 的 T_end = 643Δt）决定，不依赖问题 2 的解，因此 `resolve_interval` 阶段仍然只依赖 `detect`，可与 `resolve` 并行运行。
- **不损失可比性**：问题 2 的最优解本身满足 e_i ≤ 643（其最晚结束时刻恰为 643），因此它在受限的问题 4 模型中仍然可行；于是"问题 4 的最优向量在词典序上不劣于问题 2"这一结论在受限模型下依然成立，`compare` 阶段的断言无需修改。
- **搜索更容易**：受限模型的动作数由 6119 降到 6013、单元约束行由 41724 行规模略减，搜索空间变小，反而使更好的解可被找到——这正是评审复算观察到的现象。
- **方案 3 被否决**：题目把"是否撤销/调整"的优先级说得很清楚，再插入一级"时间范围"会改变题目给定的优先级结构（MDR-0003），且没有题面依据。

## 实现

`Limits` 增加字段 `horizon_cap`（0 表示不设限）；`enumerate_options` 在枚举出每个动作后计算 `o.apply(p).end`，超过上限的动作直接不进入动作集合（`keep` 与 `cancel` 永远保留，因为原始计划本身满足 e_i ≤ 643）。这是**在动作集合层面**施加约束，因此不需要在 CP-SAT 中增加任何约束行，模型结构不变。

独立校验器 `validators.validate_resolution` 增加 `horizon_cap` 参数，对每个存留计划独立重算 e_i 并断言 e_i ≤ 643——与求解器代码分离，因此该约束不是"自证"。

`resolve_interval` 在主结果之后再解一次**不设限**模型（`variant_time_limits`），用受限解作为热启动。由于受限解在不设限模型中可行，MDR-0009 的现任解上界割保证不设限变体报告的向量不会比受限解更差；它是否**严格更好**就直接回答了"这个约束代价几何"。

## 对结果的影响与验证

- 主结果：撤销向量由 (0,0,9)（v0.9.0，T_end = 718）变为受限模型下的解，最晚结束时刻不超过 643Δt。
- 论文第 7 节把"一个必须指出的代价"整段改写：不再宣称延长 75Δt 是必要代价。
- 摘要、第 9.2 节局限、第 9.4 节建议同步修正。
- 对照数据写入 `resolve_interval/variant_uncapped.json`，并以宏 `QfourFree*` 进入论文。
