# MDR-0014 问题 3 答案对问题 2 方案的依赖：用产物量化，而不是用轶事

日期：2026-09-12 · 状态：已采纳 · 关联问题：问题 3

## 问题

问题 3 的 109 是"在**本文这一个**问题 2 方案之上"的最大值。v0.9.0 用一句没有任何产物支撑的实验叙述来说明这种依赖：

> 本文在实验中观察到一个直接佐证：一个撤销更多计划（因而自由单元更多）的问题 2 方案，反而只能再安排更少的新增计划。

评审指出：(i) 该叙述在本轮支撑材料中没有对应产物，其来源是上一轮运行的记录；(ii) 复算结果与叙述方向相反——在本文自己的备选方案布局上，自由单元只多 0.8%，可装填数却多 21%；(iii) 更根本的是措辞会诱导错误推断：若一个布局的占用集合是另一个的子集，可装填数必然单调不减，因此"自由单元更多反而更少"本身容易被读成一个反单调性的断言。真正的变量是**布局**，不是自由单元数。

## 备选方案

1. 删去该句，只保留引理（C 类相位平铺）给出的结构性论证。
2. 删去该句，并补一个**本轮的**产物：对若干个都无冲突的问题 2 方案各跑一次装填，做成正式表格。
3. 保留叙述，补脚注说明来自上一轮。

## 决策与理由

**采纳方案 2。** 本文已经有四个经独立校验、互不相同的无冲突方案（目标方案 P/T/S/W，MDR-0003/0013），它们都是问题 2 的合法答案；在每一个之上跑同一个装填模型，代价极小（候选约 1.3×10³ 个变量，CP-SAT 秒级），却能把"109 有多依赖问题 2 的解"从定性描述变成一张可核查的表：(撤销数, 存留数, 自由单元数, 可装填数, 状态)。

方案 3 被否决：跨 run 的数字不属于本轮支撑材料，违反"论文中每个数字都来自本 run 的阶段产物"。

## 实现

`pack` 阶段读取 `resolve/alternative_decisions.json`，对每个方案的存留计划集合重建占用栅格并调用同一个 `_pack_once`，输出 `layouts.json` 与宏 `QthreeLayout*`；每个布局的装填解仍逐一送 `validators.validate_packing` 复核（与既有计划、彼此均零冲突）。

## 对结果的影响与验证

- 论文第 6.4 节删去无产物的叙述，改为引用新表；定理 6.2 的条件性（"在本文这一个问题 2 方案之上"）由该表量化。
- 第 9.2 节局限 2 给出实测区间而不是定性描述。
- 注意表中各布局的时间范围可能不同（不同方案的存留计划最晚结束时刻不同），表中单列给出，避免把不同区域的自由单元数直接相减。
